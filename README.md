# 笔记素材自动归位（attachment-router）

Obsidian 本地插件。**只对启用插件之后新建的笔记负责**：这些笔记里拖入或粘贴的图片、GIF、视频、其他素材，自动归到 Vault 根目录下的
`所有笔记素材合集/<笔记所在文件夹>/笔记名笔记素材-笔记创建时间戳/类型/`，素材文件名保持原样。笔记本身留在原位置。

启用之前就存在的笔记，以及它们引用的旧素材（比如 `assets/` 目录），插件一律不碰，也不做迁移。

作者：bayunhuiye

## 生成的结构

```
模板/
└── 火焰拖尾.md

所有笔记素材合集/
└── 模板/
    └── 火焰拖尾笔记素材-20261022-143012-123/
        ├── 图片/     png jpg jpeg webp bmp tga tif tiff avif svg
        ├── 动图/     gif apng
        ├── 视频/     mp4 mov webm avi mkv m4v wmv flv
        └── 素材/     其他一切格式（zip psd shader pdf ...）
```

笔记在几层子文件夹里，素材目录就镜像几层：`模板/特效/火焰拖尾.md` 的素材放在
`所有笔记素材合集/模板/特效/火焰拖尾笔记素材-时间戳/图片/`。这样不同文件夹里的同名笔记
（比如 `模板/测试.md` 和 `草稿/测试.md`）不会共用同一个素材目录。

总目录名称可以在插件设置中修改。如果 Vault 根目录已经存在同名笔记文件（例如
`所有笔记素材合集.md`），插件会停止归位并提示重命名笔记或修改总目录名称，避免文件和文件夹路径冲突。

## 适用范围

- 首次加载插件时，插件把当前时间写进 `data.json` 的 `enabledAt`，之后不再变化。
- 只有创建时间晚于该时间点的 `.md` 笔记才归插件管；此前创建的笔记完全跳过：不移动素材、不改写正文、不建目录。
- 在旧笔记里粘贴或拖入文件时，插件不做任何处理，文件留在 Obsidian 原本放置的位置。
- 设置页「启用」一项下方会显示当前生效时间点，方便对照。
- 如果想重新划定起点：关闭插件 → 删除 `.obsidian/plugins/attachment-router/data.json` → 重新打开插件。副作用是所有设置项回到默认值。

## 安装

1. 把整个 `attachment-router` 文件夹复制到目标库的 `.obsidian/plugins/` 下。
   插件运行需要以下文件：

   ```
   <你的库>/.obsidian/plugins/attachment-router/manifest.json
   <你的库>/.obsidian/plugins/attachment-router/main.js
   <你的库>/.obsidian/plugins/attachment-router/styles.css
   ```

   `README.md` 可一并保留，`tests/` 是开发自测，分享时不需要。

2. 打开 Obsidian → 设置 → 第三方插件 → 关闭「安全模式」（如已关闭则跳过）。
3. 在「已安装插件」里找到 **笔记素材自动归位**，打开开关。
4. 如果列表里没有，重启一次 Obsidian。

不需要联网，不依赖任何第三方插件，也不依赖 BRAT。

## 使用

正常拖拽或粘贴即可，无需任何额外操作。素材文件名**永远保留原名**，同名同后缀时自动加 `_1`、`_2`；时间戳只出现在「XX笔记素材-时间戳」这个目录名上，不会加到文件上。

- 拖进来一个 `fire.png` → `所有笔记素材合集/新笔记笔记素材-20261022-143012-123/图片/fire.png`
- 再拖进来一个 `fire.png` → `…/图片/fire_1.png`，第三个 → `…/图片/fire_2.png`
- 拖进来一个 `clip.mp4` → `所有笔记素材合集/新笔记笔记素材-20261022-143012-123/视频/clip.mp4`
- 拖进来一个 `pack.zip` → `所有笔记素材合集/新笔记笔记素材-20261022-143012-123/素材/pack.zip`

撞名只在**同一个目标分类目录**里比较，且不分大小写（Windows / macOS 上 `Fire.png` 和 `fire.png` 算撞名）。素材文件名只做必要的非法字符清洗（`\ / : * ? " < > | # ^ [ ]` 换成 `_`），其它字符原样保留。

## 设置项

设置 → 第三方插件 → 笔记素材自动归位。

页面顶部有一个提示框「请优先修改 Obsidian 中的以下设置」，把两项建议放在同一个框里（不拆成两条设置项）：

1. **自动更新内部链接**：设置 → 文件与链接 → 自动更新内部链接，保持开启（默认开启）。插件移动/改名素材时靠它同步正文里的链接；关闭后插件只会补正当前打开的笔记。
2. **检测所有文件扩展名**：设置 → 文件与链接 → 检测所有文件扩展名，打开。否则 txt、zip 等 Obsidian 不能原生打开的格式不会出现在文件列表里（文件其实已经归位，只是被隐藏）。

下面的设置项：

- 启用开关（下方显示本插件从哪个时间点开始管笔记）
- 素材根目录名（默认 `所有笔记素材合集`）
- 四个分类子目录名（图片/动图/视频/素材）
- 三组扩展名列表（英文逗号分隔）
- 等待链接写入的超时（默认 2500ms，最小 500ms：确认正文里的链接数量变多后再移动文件）
- 清理所有笔记中的未引用素材按钮、自动清理间隔（天，默认 7，填 0 关闭）
- 安全开关：只处理库根目录或笔记同目录的文件

## 行为说明

- 只处理启用后新建的笔记里新拖入、粘贴的文件；旧笔记、旧素材不碰。
- 移动使用 Obsidian 的文件管理接口，正文里的链接会随之更新。
- 素材目录按笔记所在的文件夹镜像：`所有笔记素材合集/<笔记所在文件夹…>/<笔记名>笔记素材-时间戳/`。
- 笔记改名时，素材目录段跟着换成新笔记名（时间戳不变）；笔记换文件夹时，段搬到新的镜像父目录下；旧的空文件夹会自底向上回收。
- 文件夹改名/移动时，素材总目录里对应的镜像子树整体搬过去；目标已存在同名目录时逐个合并，撞名的段留在原处并提示。
- 素材文件名保持原样（只清洗非法字符）；笔记改名只改素材目录名，不会改素材文件名，也不会给文件名加时间戳。
- 素材目录的记录丢了也能按「镜像路径 → 笔记路径」找回，不会重复建目录。
- 目录命名是 `<笔记名>笔记素材-创建时间戳`。
- 清理入口：左侧栏垃圾桶图标、笔记右键菜单「清理未引用素材」、命令面板「清理当前笔记的未引用素材」处理的是当前选中的笔记（支持文件列表多选）；设置页的「清理所有笔记中的未引用素材」按钮扫描整个素材总目录。都会先列清单确认，再移入回收站，并回收空的分类子目录和空的镜像父目录。
- 删除笔记时，只删它的「段」目录（`<笔记名>笔记素材-时间戳`），镜像父目录永远不整体删；空的镜像父目录随后自底向上回收。如果段里还有文件被其它笔记引用，目录会保留。
- 自动清理：每隔「自动清理间隔」天扫描一次整个素材总目录，把全库没人引用的素材移入回收站并清理空目录（默认 7 天，填 0 关闭）；扫描在空闲时执行，开始和结束会在右上角显示轻提示。
- 移动后遇到同名同后缀，会自动加 `_1`、`_2`；同一秒连拖多个文件也会依次拿到不同名字。
- 等不到链接时（比如拖到文件管理器而不是笔记正文里）会跳过并弹一次提示，不会硬搬。
- 移动失败会弹提示，并尽量带上具体原因，详细错误在 `Ctrl+Shift+I` 的 Console 里。

## 卸载

关掉开关，或删除整个插件文件夹。已归位的素材不会回滚。

## 已知限制

- 只处理 `.md` 笔记，Canvas 里的拖拽不生效。
- 从库内部文件树拖文件不会触发（那是移动，不是新建）。
- 启用之前创建的笔记不会被归位，这是设计如此；需要的话只能手动移动。
- 依赖「等待链接写入」的时机，机器极慢时可把超时调到 4000ms 左右。
- 插件被关闭期间改名的笔记，素材目录不会跟着改名（插件没看到那次改名）：下次拖素材会新建一个目录，旧段变成孤儿目录，需要时手动删掉或把文件挪过去。
- 清理只覆盖本插件管过的笔记（有素材目录记录的）；启用前的老笔记不提供自动清理。
- 保留原文件名意味着不同笔记里可能出现同名素材（`fire.png`）。文件本身分在不同镜像目录里，但 Obsidian 的 `![[fire.png]]` 在多个同名文件之间是**有歧义**的；建议用带路径的 `![[目录/fire.png]]`。插件在库里有同名文件时不会再批量替换正文链接，避免误伤；链接更新交给 Obsidian 的「自动更新内部链接」。
- 镜像会让素材路径变长；Windows 上笔记层级很深时注意 260 字符路径上限。
- txt/zip 这类 Obsidian 不能原生打开的类型，默认会被文件列表隐藏（设置 → 文件与链接 →「检测所有文件扩展名」，默认关闭）；打开后就能在素材目录里看到，插件本身会正常归位。
- 插件移动/改名素材依赖 Obsidian 的「自动更新内部链接」（设置 → 文件与链接，默认开启）；关闭后插件只会修正当前打开的笔记里的链接。
- 侧边栏/按钮读取多选用的是 Obsidian 文件列表的内部结构（没有公开 API）；未来版本若改动，会自动退回「只清理当前活动笔记」。
- 「启用后新建」按文件的创建时间判断。极少数拿不到创建时间的文件系统（个别 Linux 环境）上，编辑旧笔记可能让它被误判成新笔记。
