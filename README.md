# 笔记素材自动归位（attachment-router）

**简体中文** ｜ [English](README.en.md)

> **作者**：bayunhuiye ｜ **版本**：1.0.0 ｜ **最低 Obsidian 版本**：1.0.0

Obsidian 插件。这个插件只处理**启用插件之后新建的笔记**：这些笔记里拖入或粘贴的图片、GIF、视频、其他素材，会自动归到 Vault 根目录下的镜像路径里，素材文件名保持原样。笔记本身留在原位置。

启用之前就存在的笔记，以及它们引用的旧素材（比如 `assets/` 目录），插件一律不碰，也不做迁移。

## 生成的结构

```
模板/
└── 火焰拖尾.md

所有笔记素材合集/
└── 模板/
    └── 火焰拖尾笔记素材-20261022-143012-123/
        ├── 图片/     png jpg jpeg webp bmp tga tif tiff avif svg
        ├── 动图/     gif apng
        ├── 视频/     mp4 mov webm avi mkv m4v wmv flv
        └── 素材/     其他一切格式（zip psd shader pdf ...）
```

笔记在几层子文件夹里，素材目录就镜像几层：`模板/特效/火焰拖尾.md` 的素材放在 `所有笔记素材合集/模板/特效/火焰拖尾笔记素材-时间戳/图片/`。这样不同文件夹里的同名笔记（比如 `模板/测试.md` 和 `草稿/测试.md`）不会共用同一个素材目录。

总目录名称可以在设置里修改。如果 Vault 根目录已经存在同名笔记文件（例如 `所有笔记素材合集.md`），插件会停止归位并提示改名，避免文件与文件夹路径冲突。

## 安装

### 方式一：手动安装

把整个 `attachment-router` 文件夹复制到目标库的 `.obsidian/plugins/` 下，需要这三个文件：

```
<你的库>/.obsidian/plugins/attachment-router/manifest.json
<你的库>/.obsidian/plugins/attachment-router/main.js
<你的库>/.obsidian/plugins/attachment-router/styles.css
```

然后打开 Obsidian → 设置 → 第三方插件 → 关闭「安全模式」→ 在「已安装插件」里找到 **笔记素材自动归位**，打开开关。列表里没有就重启一次 Obsidian。

### 方式二：从 GitHub 下载

从仓库下载 `main.js`、`manifest.json`、`styles.css`，放进 `<你的库>/.obsidian/plugins/attachment-router/` 再启用。

### 方式三：BRAT 安装

先装 [BRAT](https://github.com/TfTHacker/obsidian42-brat)，然后在 BRAT 设置里 Add Beta plugin，填 `bayunhuiye/attachment-router`。

## 使用

正常拖拽或粘贴即可，无需额外操作。素材文件名**永远保留原名**，同名同后缀时自动加 `_1`、`_2`；时间戳只出现在 `XX笔记素材-时间戳` 这个目录名上，不会加到文件上。

- 拖入 `fire.png` → `所有笔记素材合集/新笔记笔记素材-20261022-143012-123/图片/fire.png`
- 再拖入 `fire.png` → `…/图片/fire_1.png`，第三个 → `…/图片/fire_2.png`
- 拖入 `clip.mp4` → `…/视频/clip.mp4`
- 拖入 `pack.zip` → `…/素材/pack.zip`

撞名只在**同一个分类目录**里比较，且不分大小写（Windows / macOS 上 `Fire.png` 和 `fire.png` 算撞名）。文件名只做必要的非法字符清洗（`\ / : * ? " < > | # ^ [ ]` 换成 `_`）。

拖到文件管理器而不是笔记正文里时，等不到链接写入，插件会跳过并提示，不会硬搬。

## 设置

设置 → 第三方插件 → 笔记素材自动归位。页面顶部有一个提示框，建议先确认 Obsidian 的两项设置：

1. **自动更新内部链接**（设置 → 文件与链接）：保持开启。插件移动或改名素材时靠它同步正文链接；关闭后只会补正当前打开的笔记。
2. **检测所有文件扩展名**（设置 → 文件与链接）：打开。否则 txt、zip 等 Obsidian 不能原生打开的格式不会出现在文件列表里（文件其实已经归位，只是被隐藏）。

插件自身的设置项：

| 项 | 说明 |
|---|---|
| 启用 | 总开关，下方显示本插件从哪个时间点开始管笔记 |
| 素材根目录名 | 默认 `所有笔记素材合集` |
| 分类子目录名 | 图片 / 动图 / 视频 / 素材，四个都可改 |
| 扩展名列表 | 三组，英文逗号分隔 |
| 等待链接写入超时 | 默认 2500ms，最小 500ms |
| 自动清理间隔 | 天数，默认 7，填 0 关闭 |
| 安全开关 | 只处理库根目录或笔记同目录的文件 |

想重新划定起点：关闭插件 → 删除 `.obsidian/plugins/attachment-router/data.json` → 重新打开插件。副作用是所有设置回到默认值。

## 清理未引用素材

三个入口，处理范围不同：

- 左侧栏垃圾桶图标、笔记右键菜单「清理未引用素材」、命令面板「清理当前笔记的未引用素材」——处理当前选中的笔记（支持文件列表多选）
- 设置页的「清理所有笔记中的未引用素材」按钮——扫描整个素材总目录

都会先列出清单让你确认，再移入回收站，并回收空的分类子目录和空的镜像父目录。

插件还会按「自动清理间隔」定期扫描整个素材总目录，把全库没人引用的素材移入回收站并清理空目录。扫描在空闲时执行，开始和结束会有轻提示。

## 笔记改名或移动时

素材目录会跟着走：

- 笔记改名 → 素材目录段换成新笔记名，时间戳不变，素材文件名也不动
- 笔记换文件夹 → 整段搬到新的镜像父目录下，旧空目录自底向上回收
- 文件夹改名或移动 → 素材总目录里对应的镜像子树整体搬过去；目标已有同名目录时逐个合并，撞名的段留在原处并提示

## 已知限制

- 只处理 `.md` 笔记，Canvas 里的拖拽不生效；从库内文件树拖文件也不触发（那是移动，不是新建）。
- 启用之前创建的笔记不会被归位，这是设计如此；需要的话只能手动移动。
- 清理只覆盖本插件管过的笔记（有素材目录记录的），老笔记不提供自动清理。
- 保留原文件名意味着不同笔记里可能出现同名素材（`fire.png`）。文件分在不同镜像目录里，但 Obsidian 的 `![[fire.png]]` 在多个同名文件之间**有歧义**，建议用带路径的 `![[目录/fire.png]]`。库里有同名文件时插件不会再批量替换正文链接，交给 Obsidian 的「自动更新内部链接」。
- 插件被关闭期间改名的笔记，素材目录不会跟着改名：下次拖素材会新建目录，旧段变成孤儿目录，需要时手动清理。
- 依赖「等待链接写入」的时机，机器极慢时可把超时调到 4000ms 左右。
- 镜像会让素材路径变长，Windows 上笔记层级很深时注意 260 字符路径上限。
- 「启用后新建」按文件创建时间判断。极少数拿不到创建时间的文件系统上，编辑旧笔记可能让它被误判成新笔记。

## 卸载

关掉开关，或删除整个插件文件夹。已归位的素材不会回滚。
